# 候选方案对比实验报告

> 目标：评估是否有更新的方法能在 NHANES 数据上**提升预测准确率并提高可解释性**
> 评测口径：与 `run.py` 堆叠集成基线**完全相同的队列划分与验证方式**
> 训练 2013-2016 / 内部验证 2017-2018 / **外部验证 2021-2023（跨年代漂移）**
> 运行日期：2026-10-13　固定随机种子 42

---

## 一、结论摘要

**平均外部验证 AUC 排名（2021-2023）**

| 排名 | 模型 | 平均外部 AUC | 相对基线 | 训练样本 | 单病种耗时 | 可解释性 |
|---|---|---|---|---|---|---|
| 🥇 | **TabPFN（5,000 子样本）** | **0.8206** | **+0.0010** | **5,000** | **≈20 分钟** | ❌ 黑盒 |
| 🥈 | 堆叠集成（基线，全量） | 0.8196 | — | ≈10.5k | 数秒 | SHAP 事后近似 |
| 🥉 | EBM（全量） | 0.8170 | -0.0026 | ≈10.5k | 数秒 | **✅ 玻璃盒** |
| 4 | AutoGluon（受限，全量） | 0.8151 | -0.0045 | ≈10.5k | 40 秒 | 集成，需额外解释 |
| 5 | EBM（5,000 子样本） | 0.8091 | -0.0105 | 5,000 | 数秒 | ✅ 玻璃盒 |

**四条结论：**

1. **TabPFN 是精度最高的方案，且只用了不到一半的训练数据**（5,000 vs 全量约 10,500）。它以 +0.0010 微弱超越全量堆叠集成，对同子样本的 EBM 领先 **+0.0114**。**这证明表格基础模型在数据效率上有真实优势。**

2. **TabPFN 的优势集中在基线的弱项病种**：中风 +0.0066、慢性肾病 +0.0083、糖尿病 +0.0055（5/7 病种优于全量基线）。这对症下药的价值很高。

3. **但代价是三个硬约束**：训练样本不能超过约 5,000（本机实测）、单病种推理约 20 分钟、**完全黑盒无可解释性**。详见第三节。

4. **模型侧的提升空间确实很小**：五个方案（含差异极大的方法族）全部落在 **0.8091–0.8206** 的 0.0115 区间内。这仍是**信号瓶颈**的典型特征——真正的提升要靠纵向特征与标签质量，而非换模型。

### 一句话选型建议

- 要**精度**且能接受黑盒与慢推理 → **TabPFN**（但仅适用于 ≤5,000 样本场景）
- 要**可解释性**且几乎不损失精度 → **EBM**（-0.0026）
- 要**兼顾**且场景规模大 → **堆叠集成**作主力 + **EBM** 作可解释性报告模型

### 3.2 三个硬约束（实测）

| 配置 | 结果 |
|---|---|
| MPS（Apple GPU），11,380 样本 | ❌ **显存溢出** — `MPS allocated: 7.89 GiB, max allowed: 8.29 GiB`，仍差 472 MiB |
| CPU 全量，默认设置 | ❌ **拒绝 >5,000 样本** — `Running on CPU with more than 5000 samples is not allowed by default due to slow performance` |
| CPU 全量 + `TABPFN_ALLOW_CPU_LARGE_DATASET=1` | ⚠️ **单次 fit 超 10 分钟** — 7 病种 × 6 次拟合需 7 小时以上 |
| **CPU 5,000 子样本** | ✅ 可行，但单病种约 20 分钟 |

**成本结构的关键**：TabPFN 是上下文学习器，`fit` 只耗时 **0.8 秒**（仅存储数据），而 `predict 5,000 行需 213 秒`。**全部成本在推理**，这是注意力机制的固有开销，无法通过配置规避。

### 3.3 对大规模队列项目的含义

**TabPFN 与十万量级队列相差两个数量级，不具可行性。** 它的定位应是**小样本基准工具**：当需要在少量标注样本上快速判断某组特征是否有信号时，TabPFN 很有价值；作为大规模型的主力模型不现实。

此外它**没有可解释性**，与"提高可解释性"的目标相反。

## 四、EBM 的可解释性产出（本次核心收益）

EBM 的形式是 **加性模型**：

```
预测 log-odds = 截距 + Σ 每个特征的形状函数值 + Σ 成对交互项
```

这意味每个指标对风险的贡献**可以直接画成一条曲线**，且与模型真实决策路径**严格一致**——不是 SHAP 那种对黑盒的近似，更不是 LLM 的事后叙事。

产出文件：
- `reports/ebm_importance_<disease>.csv` — 各特征重要性与增减方向
- `reports/figures/ebm_shapes_<disease>.png` — 顶部特征的形状函数曲线

### 各病种 Top 特征

| 病种 | 最重要特征（重要性） |
|---|---|
| 高血压 | 年龄 0.851 · BMI 0.330 · 钾 0.138 · 钙 0.137 |
| 糖尿病 | 年龄 1.405 · BMI 0.379 · 甘油三酯 0.272 · 总胆固醇 0.245 |
| 癌症 | 年龄 0.772 · **年龄×性别 0.155**[交互] · 淋巴细胞% 0.093 |
| 冠心病 | 年龄 0.955 · 血小板 0.167 · **MCV×年龄 0.152**[交互] |
| 心梗 | 年龄 1.032 · RDW 0.205 · 性别 0.162 |
| 中风 | 年龄 0.605 · 肌酐 0.105 · RDW 0.088 |
| 慢性肾病 | 年龄 0.265 · 红细胞 0.118 · 钾 0.097 · MCV 0.088 |

### 两个值得注意的点

**① EBM 自动发现了有临床意义的交互项**，无需人工指定：
- 癌症：**年龄 × 性别**（男性/女性的年龄-癌症风险曲线形状不同）
- 癌症：**红细胞 × 年龄**
- 冠心病：**MCV × 年龄**

这类交互在纯加性模型（如逻辑回归）中捕捉不到，而 EBM 能自动学出来**并保持可解释**（交互项本身也是一张二维热图）。

**② 与 SHAP 结果高度一致（收敛效度）。** EBM 的 Top 特征与堆叠模型的 SHAP 排序基本吻合——年龄全面主导、BMI 次之、血常规分类计数与红细胞参数广泛入选。两个独立方法给出一致结论，增强了结果的可靠性。

## 五、环境障碍记录（影响结论解读，须如实说明）

### 5.1 TabPFN 许可（已解决）

TabPFN 要求**一次性许可确认**才能下载权重。经接口核验定位到具体缺环：

```
GET /account/license/?version=priorlabs-1-1  →  {"accepted": false}
GET 验证 token                                →  True（Key 本身有效）
```

即：创建 API Key 不等于接受许可，还须在 <https://ux.priorlabs.ai> 的 **Licenses 标签页**勾选接受。用户完成该步骤后，权重成功下载、推理正常。

**另需注意**：`tabpfn` 的 `_get_license_name()` 硬编码请求 `huggingface.co`，而本机直连被墙，因此运行**必须挂代理**（`HTTPS_PROXY=http://127.0.0.1:7890`），仅设 `HF_ENDPOINT` 镜像无效。

### 5.2 AutoGluon 的 GBDT 后端在本机段错误

`GBM`(LightGBM) 与 `XGB` 在 AutoGluon 内**触发 SIGSEGV**（exit 139），而独立调用 XGBoost 正常。这是 macOS 上典型的 **OpenMP 运行时冲突**（Homebrew 的 `libomp` 与 wheel 内置的 OpenMP 重复加载）。

实测以下规避手段**均无效**：
- `KMP_DUPLICATE_LIB_OK=TRUE`
- `OMP_NUM_THREADS=1`
- 二者组合

因此 AutoGluon 只能用安全子集 `RF / XT / KNN / LR / NN_TORCH / REALMLP / TABM`。**这意味着它无法动用最强的 GBDT 成员，-0.0045 的差距中有多少来自这一点无法区分**，需据此审慎解读。

另外：**AutoGluon 1.6.3 内置了 `TABPFN-2.6`、`TABICL`、`TABM`、`TABPFN-3` 等表格基础模型**，是一条备用路径，但 `TABPFN-2.6` 同样受许可门槛限制、`TABICL` 报"无模型训练成功"，唯一跑通的是 **`TABM`**（高血压训练内 AUC 0.8612）。

### 5.3 依赖降级

安装 AutoGluon 时 pip 将 `pandas 3.0.6 → 2.3.3`、`pyarrow 26.0.0 → 24.0.0`。已验证现有管线（`data.py`、`metrics.py`、`build_cohort`）在降级后仍正常工作。

## 六、对"如何真正提升准确率"的判断

本次实验给出的是一个**重要且部分负面**的结论：**模型侧已接近该数据的性能上限**。五个差异极大的方法族（堆叠集成、可解释 GAM、自动集成、表格基础模型、以及同子样本对照）全部收敛到 **0.8091–0.8206** 的 0.0115 区间内，这通常是**信号瓶颈**的典型特征——数据中可提取的判别信息已经用得差不多了。

TabPFN 的 +0.0010 提升虽有价值（尤其对弱项病种 +0.0066~+0.0083），但幅度远小于换用新方法通常的预期。因此提升应转向数据与特征侧，按预期收益排序：

| 优先级 | 方向 | 依据 | 预期收益 |
|---|---|---|---|
| ⭐⭐⭐ | **纵向特征** | 具备多次随访检验的队列可构造趋势特征；NHANES 是横断面，**本次实验完全无法体现这一优势** | 高 |
| ⭐⭐⭐ | **标签质量** | NHANES 是自报诊断（未诊断者被错分为阴性），电子病历确诊标签质量更高 | 高 |
| ⭐⭐ | **类别不平衡** | 中风 3.4%、慢性肾病 3.6%，EBM/AG 在这两项表现最差 | 中 |
| ⭐⭐ | **凝血项等缺失指标** | NHANES 无 PT%/纤维蛋白原 | 中（视病种） |
| ⭐ | 模型替换 | 本次实验已证伪 | **低** |

**最重要的一条**：NHANES 的横断面结构让我们**无法测试纵向建模的收益**——而纵向结构恰恰是临床队列相对公开数据集的核心优势。因此本次"模型侧无提升空间"的结论**不能外推到其他队列**，那里真正值得投入的是时序特征工程。

## 七、建议

1. **可解释性：立即采用 EBM。** 精度代价仅 0.0026，换来完全可审计的加性模型与形状函数曲线。这对临床场景的价值远超 0.0026 的 AUC。建议作为**主报告模型**，与堆叠集成并行发布。

2. **准确率：TabPFN 值得在小样本场景试用，但不适用于十万量级队列。** 它在 ≤5,000 样本时精度最高（0.8206），且对弱项病种（中风、慢性肾病）有 +0.007~+0.008 的实质改善——**这些场景值得单独尝试**。但其规模上限、20 分钟/病种的推理成本、以及黑盒属性，使它无法成为大规模型的主力。

3. **主力模型维持堆叠集成，停止在模型侧继续投入。** 五个方法族收敛在 0.0115 区间内，说明继续试模型收益极低。真正的提升在纵向特征工程与标签质量。

4. **交叉验证结论**：EBM 与 SHAP 的特征排序高度一致，说明"年龄主导、血常规分类计数与红细胞参数为核心信号"这一发现是稳健的，可直接用于实际队列的变量优先级排序。
